核心设计

小而完整：Agent-as-Tool、插件目录、双协议与轨迹可视化。

↗

Agent as Tool

子智能体对 Manager 表现为普通函数（单参数 task），各自独立记忆与 ReAct 循环。

◈

一切即插件

ToolRegistry 统一管理能力。内置工具与运行时 create_tool 注册的动态工具一视同仁。

▣

沙箱工作区

read / write / shell / search 限制在 workspace 内，路径逃逸被拒绝，命令带超时。

协作关系

Manager 调度成员；成员调用插件；模型还可扩展插件目录。

内置插件

开箱即用的底层能力；create_tool 让模型继续扩展。

read读取工作区内文本文件
write写入 / 创建文本文件
list_dir列出目录内容
shell在工作区执行 shell（30s 超时）
search递归文本搜索
calculator简单四则运算
create_tool元插件：用 shell 模板注册新工具，立即调用
final_answer结束 ReAct 循环并返回答案

快速开始

Go 1.22+，配置 API 后一条命令即可跑起来。

terminal 
# 克隆并配置
git clone https://github.com/1parado/tiny-team.git
cd tiny-team
cp .env.example .env
# 编辑 .env：PROTOCOL / BASE_URL / API_KEY / MODEL

# 运行
go run . -task "在 workspace 写 hello.txt 并读回来"

# 可选：轨迹 UI、自定义沙箱目录
go run . -web :8765 -workspace ./myws -task "..."

go test ./... -count=1

create_tool 示例

模型在对话中注册新工具，后续步骤即可直接调用。

create_tool arguments 
{
  "name": "count_lines",
  "description": "Count lines in a file",
  "parameters": {
    "type": "object",
    "properties": { "path": { "type": "string" } },
    "required": ["path"]
  },
  "command": "wc -l {{path}}"
}
